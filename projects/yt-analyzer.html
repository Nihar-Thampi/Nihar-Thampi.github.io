What it’s for

YouTube’s analytics tell a creator how many people watched. They don’t say what those people thought, and nobody has time to read every comment to find out.

The analyzer reads them for you. Paste a video link and it measures how viewers feel compared with the tone of the video itself, summarises what they said while leaving out off-topic chatter, writes recommendations for the creator, and lets you ask questions about the comments in a chat that answers only from what viewers actually wrote.

Everything runs on local models, with no per-call cost, and each account’s videos, keys and results are kept separate.

How a video is analysed

  1. Collect

    The video’s metadata and comments come from the YouTube Data API. If the API quota runs out and the user has enabled it, a headless Selenium scraper takes over and returns the same shape of data.

  2. Hand off to the background

    The request returns straight away and the analysis runs as a background task. The dashboard polls every four seconds and shows which step is running.

  3. Read the transcript first

    The transcript is fetched and summarised with DistilBART, in chunks and then once more over the combined summaries, because a 20-minute video doesn’t fit in one pass. Its sentiment becomes the video’s own tone, and its topic grounds every later step. Without captions, the later steps fall back to versions that don’t need it.

  4. Score every comment

    SieBERT classifies each comment. When its confidence is below 0.70, the comment is scored again by BART-MNLI as zero-shot classification against the video’s topic, so slang like “this is sick” on a gaming video reads as praise.

  5. Summarise and advise

    Mistral 7B summarises the comments in light of the transcript and is told to leave out off-topic ones. It then interprets the sentiment numbers in a few sentences and writes five recommendations for the creator.

  6. Index for questions

    The comments are embedded with all-MiniLM-L6-v2 into a FAISS index saved for that video. A question pulls the closest comments, and Mistral answers only from them, or says it can’t answer.

What it does

Analysis

  • Positive, negative and neutral shares of the comments
  • Viewer sentiment compared with the video’s own tone
  • A written interpretation of the numbers
  • A comment summary that ignores off-topic replies

For the creator

  • Five concrete recommendations based on viewer feedback
  • A chat for questions like “why did people dislike this?”
  • A table of every comment with its sentiment

Accounts

  • JWT sign-in with bcrypt-hashed passwords
  • Each user’s videos, API key and analytics kept separate
  • Several videos per account, switchable from the sidebar

Hardware

  • NVIDIA GPUs in float16, Apple Silicon through MPS, and CPU in bfloat16
  • Models load on first use

Decisions and trade-offs

One 7B model, four jobs

Summaries, interpretation, recommendations and chat all share a single loaded Mistral instance with greedy decoding, so results are repeatable and a 7B model is only held in memory once.

Pay for the expensive model only when needed

SieBERT is fast and right most of the time. The heavier zero-shot check runs only on comments it’s unsure about.

Exact search is enough

A video has hundreds of comments, not millions, so a brute-force FAISS index is exact and needs no tuning. Searching across every video would need an approximate index.

What I’d change next

Background tasks run in the API process and pipeline status lives in memory, so a restart mid-analysis loses the job. A proper job queue and stored status would fix both.
